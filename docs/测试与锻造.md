# 测试与锻造：当前生效规则

2026-11-04 用户确认：五次锻造代表同一道题累计五次测试通过，不是五种能力任务。

## 一致的流程

1. 完成整理并补充参考答案，才能开始测试。
2. 独立作答后提交，提交期间锁定输入。心得可选填，不影响是否通过。
3. 判题明确正确或错误后自动保存测试记录；正确推进一阶，错误不推进、不扣除先前成功次数。
4. 累计五次正确即完成锻造。允许同一天完成，不要求连续正确，没有第三阶讲解、第四阶变式或第五阶隔天门槛。
5. 完成后仍可额外练习，进度最多五阶。重新安排复习只设置提醒，不取消完成标记。
6. 判题无法确定、服务不可用、保存失败时不展示成功完成。保存失败可重试同一个提交标识，不重复增加次数。

云端测试提交前会强制请求服务器 `GET /api/time`，复习记录使用服务器返回的 UTC 时间；时间服务不可用时本次测试不保存。阶段仍允许连续提交，`interval` 只用于生成复习提醒。

修改题干、参考答案或原题图片时，旧测试归档并保留在历史中，当前题目从零累计；修改标题、标签或备注不重置进度。

动画仍依次为选材、锻形、淬火、磨刃、成锋，仅表现累计通过次数。

旧自评历史保留但不计入判题通过次数；有旧锻造历史的题目加载时会按实际判题记录重新计算完成标记。统计中的测试通过率只包含判题记录。

## 页面职责

首页负责收录、最近记录和简短练习提醒，提醒跳转练习页。练习页负责到期测试、自主测试和计划；成长记录显示统计。

## 判题范围

本地保守识别单个 A–H 选项、纯数字、分数和百分数，使用精确有理数比较。明确要求步骤、证明或解释的题目及带原图的题目直接交给 AI，并携带原题图片；其他无法可靠比较的表达也交给 AI 辅助判题。无法可靠判断时返回 unresolved，不推进。

本地 `npm run dev:ai` 使用 `.env.local` 中的 `MIMO_API_KEY`。密钥不得进入客户端。Node/Netlify 和 VPS Go 服务复用 `/api/question-generate` 的 `operation: assess` 模式。本地已配置 MiMo Flash。2026-11-05 已实测遗漏必要步骤判错、完整解答判对、原题图片识别判题；这些样例验证不代表所有题型都能可靠自动评分。

## 验证

- `npm run verify:forge`：累计五次通过、错误不回退、重复提交、旧自评隔离、备份与排期。
- `npm run verify:assessment`：精确数值核对、上游判题协议和错误处理。
- `.validation/five-tests-browser-qa.cjs`：首页分工、真实客观判题、同日五次通过、刷新后的进度与历史。
