# 快速收录与待处理

## 课堂演示流程

1. 首页点击“添加错题”。流程统一为“录入题目 → 核对入库”，文字录入、拍照/上传和电脑拖图都进入同一个收录窗口。
2. 文字可直接粘贴题干；图片保留原图，并可选择本机 OCR 提取文字后校对。没有识别好时也能先存图。
3. 录入界面可选“待会整理”或“AI 辅助整理”，默认待会整理。前者点击“存入待处理”后保持科目、难度、标签、参考答案、解析空白，不调用 MiMo；首页与错题集显示待处理数量。
   选择“AI 辅助整理”只改变下一步动作，不会立即调用接口。点击“下一步：AI 整理”后，先成功保存同一道待处理题，再进入核对页并发起一次生成；失败仍可在待处理中找到原题。普通再次打开题目不会自动重复调用。
4. 点击待处理卡片即可继续整理，不再先打开题目档案。可手动完善，或点击“开始 AI 整理”。手动表单按题目、分类标签、答案解析排列，标题/来源/原作答折叠为选填项。
5. AI 生成期间显示进度；生成后只展示结果与原图对照，不再重复展示空表单。核对无误点击“确认并入库”，一次确认即可完成；需要修改则点击“修改内容”进入表单，最后点击“完成整理”。未确认的结果不会写入题目，关闭时会说明原题保留、AI 建议未保存。
6. 手动“保存到待处理”后返回待处理列表；“完成整理”或 AI“确认并入库”后进入已整理列表并打开题目档案。更新同一个 ID，不创建第二份题目。首页待处理入口与最近整理分开展示，待处理题不会重复出现在最近整理中。

## 数据与统计

- 整理状态 `organizationStatus` 与掌握状态 `status` 分开。旧题、旧草稿和旧 JSON 备份兼容；旧题默认已整理，不需要重新处理。
- 收录总数含待处理；学科、难度、掌握率、复习和组卷只使用已整理题目。
- 完成整理必须有有效科目和难度，答案、解析可后补；独立重做仍需参考答案。
- 处理更新同一题目的 ID，保留 `createdAt`，记录 `organizedAt`。待处理没有复习日期，完成整理后可以自主安排日期。
- 本地存储失败时界面保留输入并明确提示，重试沿用题目 ID。浏览器或小程序数据仍只属于当前设备，JSON 备份规则不变。

## 识别方式

- 网页版本地 OCR 在浏览器内运行，只提取文字，不推断答案或分类。不需要 MiMo Key；首次使用仍需下载自托管的识别引擎和中英文模型，后续可复用缓存。
- OCR 识别出的数学符号和中文可能有误，需对照原图校对；原图一直保留。
- 电脑网页可在快速收录窗口内直接拖入本地 JPG、PNG、WebP 图片，每张不超过 2MB，同一道题最多 3 张。有效图片批量读完后自动启动一次本机 OCR；即使当前是文字录入，也会切换到题图模式。已有手输题干不会被自动覆盖，识别结果仍需核对并点击“填入题干”。
- 重复、过大、损坏或不支持的文件会提示；全批无效时不启动识别，也不会中断已有识别。网页图片链接不自动下载，先保存到电脑再拖入。关闭收录窗口会结束本次识别。
- 微信小程序先支持保存原图、文字输入和后续智能整理。浏览器 OCR 的 Web Worker / WebAssembly 不能直接作为小程序 OCR 使用，小程序包不附带这些模型。
- MiMo 需要在自己的服务端配置密钥。Sites 演示站已使用同源 Worker 接口；腾讯部署仍需配置相应服务端。接口失败时保留原题并允许重试或手动整理；保存失败只重试保存，不自动再次请求模型。

## 耗时口径

分别记录选图后的文字识别、点击保存后的持久化、后续智能整理三段耗时。首次模型下载与初始化应计入首次识别；同一引擎再次识别属于缓存复用场景。桌面本地测试结果不能当作公网手机真机速度，演示时可展示实际等待与进度。
